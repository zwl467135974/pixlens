# 04 性能要求

> 状态：已定稿 | 决策日期：2026-09-20
> 本文档是**验收标准**而非软性目标。每个里程碑结束后按本文测量并记入 `doc/验收记录.md`。

## 1. 性能指标验收表

| # | 指标 | 目标值 | 验收场景 | 测量方法 |
|---|---|---|---|---|
| P1 | 冷启动 | < 1s | 双击图标 → 首屏可交互（空态页） | 进程启动时间戳与首屏渲染埋点差值 |
| P2 | 大文件夹扫描 | 10k 文件 < 2s | 仅元数据枚举，SSD 与 HDD 各测一次 | scan 命令内部计时日志 |
| P3 | 首屏缩略图 | < 500ms | 冷缓存下扫描完成后，前 60 张可见缩略图出图 | 缩略图管线埋点 |
| P4 | 缩略图墙滚动 | 60fps，持续白屏不超过 200ms | 1 万张混合格式，快速拖动滚动条 | 前端 rAF 帧率统计 |
| P5 | 缩略图缓存 | 二次打开秒出 | 同一文件夹第二次打开 | 首帧出图时间埋点 |
| P6 | 翻页响应 | 已预取 < 16ms；未预取 < 200ms | 查看器内连续方向键翻页 | 前端埋点（预取窗口 ±2 张） |
| P7 | 大图缩放平移 | 60fps | 50MP（8688×5792）JPG，100% 缩放拖动 | 查看器帧率统计 |
| P8 | 巨型 PSB | 内嵌缩略图 < 100ms；合成预览 < 2s | 约 2GB 的 PSB 文件 | 管线埋点 |
| P9 | 内存-负载态 | < 400MB 稳定 | 万张缩略图墙滚动 5 分钟后 | 任务管理器 / 进程内存统计 |
| P10 | 内存-空闲 | < 120MB | 打开空文件夹静置 | 同上 |
| P11 | 安装包体积 | < 15MB | NSIS 发布产物 | 文件大小 |
| P12 | 磁盘缓存 | 默认上限 1GB，可配 256MB~8GB | 设置页修改后生效 | 设置项验证 |

## 2. 指标 → 设计保障映射

| 指标 | 依赖的设计决策（见《03-架构设计》） |
|---|---|
| P1 冷启动 | Tauri 无捆绑 Chromium；启动即渲染空态页，扫描异步 |
| P2/P3 扫描与首屏 | 扫描仅 stat 元数据不开文件；缩略图管线信号量限流 + 视口优先 |
| P4 滚动 | 前端虚拟滚动（只渲染可见行 ±2 行缓冲） |
| P5 缓存命中 | 磁盘缓存键 = blake3(路径+大小+mtime) |
| P6 翻页 | 预取 ±2 张进内存 LRU |
| P7 大图 | Canvas 变换矩阵 + Rust 端降采样预览分级加载（LOD） |
| P8 巨型 PSB | 1036 内嵌缩略图快路径 + mmap + rayon 并行合成 |
| P9/P10 内存 | 解码即用即弃、缩略图只有磁盘缓存不长期驻留、内存 LRU 定容 |
| P11 体积 | 无框架前端 + Rust 依赖最小化 |

## 3. 基准测试方案

### 3.1 合成图库生成（tests/ 下脚本）

生成标准测试图库，参数可调，用于 P2~P9 验收：

| 图库 | 构成 | 用途 |
|---|---|---|
| LIB-S（1 千张） | 混合 JPG/PNG/GIF/WebP，尺寸 0.5~5MP | 冒烟 |
| LIB-M（1 万张） | 同上分布 | P2/P3/P4/P9 主战场 |
| LIB-XL（超大图） | 50MP JPG × 20 | P7 |
| LIB-PSB | 构造 2GB 级 PSB（程序生成填充图）+ 含/不含内嵌缩略图各一 | P8 |
| LIB-TIFF | 多页 TIFF × 50、32 位 HDR × 20 | M4 验收 |

生成方式：Node 或 Rust 小工具按需生成（JPG/PNG 可直接编码；PSB 用 03 §6 结构写 Raw/RLE 合法文件）。

### 3.2 埋点规范

- Rust：`tracing` 计时日志，关键路径（scan/decode/encode/cache-hit）输出毫秒耗时
- 前端：性能标记（rAF 帧率统计、翻页耗时、首屏出图时间）
- 验收脚本汇总输出一张表，结果写入 `doc/验收记录.md`，注明日期与机器状态

### 3.3 验收流程

1. 每个里程碑（M1、M2、M3、M7 必做；其余抽查相关项）结束时跑相关指标
2. 未达标 → 当期修复，不带病进入下一期
3. M7 做全量 12 项指标终验

## 4. 稳定性护栏（与性能同级的硬要求）

- 损坏文件/非图片改后缀：显示占位图标，进程不崩、不阻塞其他图
- 解码限额：单图尺寸上限 30 万像素边长、单次解码内存上限 1.5GB，超限走占位
- 并发限流：缩略图解码并发 = min(物理核数-1, 8)，UI 永远让出资源
- 解码炸弹（decompression bomb）防护：超限直接拒绝
