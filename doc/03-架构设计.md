# 03 架构设计

> 状态：已定稿 | 决策日期：2026-09-20
> 本文定义 PixLens 的总体架构、模块职责、数据流与关键技术设计，实施时按此展开。

## 1. 总体架构

```
┌───────────────────────────────────────────────────────────────┐
│                 WebView2 前端（TypeScript，无框架）              │
│  ┌───────────┐ ┌───────────┐ ┌────────────┐ ┌──────────────┐  │
│  │ 缩略图墙   │ │ 大图查看器 │ │ 批量/编辑面板│ │ 设置/状态栏   │  │
│  │ (虚拟滚动) │ │ (Canvas)  │ │            │ │              │  │
│  └─────┬─────┘ └─────┬─────┘ └─────┬──────┘ └──────────────┘  │
│        │ thumb://      │ image://   │ invoke（仅小 JSON 消息）  │
├────────┼───────────────┼────────────┼──────────────────────────┤
│        ▼               ▼            ▼                          │
│                      Tauri 2 核心（Rust）                       │
│  ┌─────────────────────────────────────────────────────────┐  │
│  │ 协议层：thumb://（缩略图）  tile://（大图分块，M2+）        │  │
│  │ 命令层：scan_folder / batch_* / edit_*（serde JSON）      │  │
│  ├─────────────────────────────────────────────────────────┤  │
│  │ 服务层：扫描器 │ 缩略图管线 │ 缓存管理(LRU) │ notify 监听  │  │
│  ├─────────────────────────────────────────────────────────┤  │
│  │ 解码层：image crate │ PSD/PSB 自研解析器 │ TIFF 多页      │  │
│  │        rayon 并行池 │ memmap2 零拷贝 │ 信号量限流         │  │
│  └─────────────────────────────────────────────────────────┘  │
└───────────────────────────────────────────────────────────────┘
```

**核心原则：大数据（像素字节）一律走自定义协议直传，JSON IPC 只走小控制消息。**

## 2. 进程与线程模型

| 执行体 | 职责 | 并发策略 |
|---|---|---|
| WebView UI 线程 | 渲染、交互、Canvas 绘制 | 单线程，绝不做解码 |
| Tauri 协议线程 | 处理 `thumb://` 等请求 | 每请求一线程，经信号量（ permits = min(物理核数-1, 8) ）限流后进入解码 |
| rayon 全局池 | CPU 密集解码（缩放/重编码/PSD 合成） | 池大小 = 物理核数，任务粒度 = 单通道行块 |
| notify 监听线程 | 文件夹变更 → 事件 → 前端增量刷新 | 单线程，防抖 300ms |

## 3. 模块设计

### 3.1 扫描器（scan.rs）

- `walkdir` 递归枚举，按扩展名白名单过滤图片文件
- 仅收集元数据（名称/路径/扩展/大小/mtime），不打开文件内容
- 返回 `Vec<Entry>`（10k 条 JSON 约 2MB，序列化 <100ms，可接受；超大规模再改事件流分批）
- `notify` 监听已打开文件夹，变更事件防抖后推送到前端做增量增删改

### 3.2 缩略图管线（thumb.rs）

请求处理流程：

```
thumb:// 请求(src, w)
  → 缓存键 = blake3(src路径 + size + mtime)[..24] + w
  → 磁盘缓存命中？ → 直接返回 JPEG 字节
  → 未命中：
      → 信号量准入（并发限流）
      → 按扩展名分发解码：
          PSD/PSB → 1036 内嵌缩略图快路径（<1ms 级）
                    → 无内嵌则合成图解码（超大文件见护栏）
          常见格式 → image crate 解码（设尺寸/内存限额）
          AVIF/SVG → 透传原始字节给 WebView 解码
      → 缩放到目标宽（保持宽高比）→ JPEG 编码(质量 82)
      → 写入磁盘缓存 → 返回字节
```

- 前端 `<img src="thumb://...">`，浏览器并发加载形成天然背压
- 视口优先：浏览器按 DOM 顺序请求可见项，天然优先级；如需更强控制再加请求队列

### 3.3 大图查看器（viewer.rs + 前端 Canvas）

分级加载策略（LOD）：

| 图片规模 | 策略 |
|---|---|
| ≤ 屏幕尺寸×2 | 全量解码，直接绘制 |
| 中大图（≤100MP） | 先解码降采样预览（贴合屏幕），放大到 100% 时全量解码替换 |
| 巨型图（>100MP，如大 PSB/TIFF） | 预览 + `tile://` 按需分块解码（视口 ROI），v1.1 完善金字塔 |

- 前端 Canvas 负责变换矩阵（缩放/平移/旋转/翻转），Rust 只出像素
- 翻页预取：当前图 ±2 张预解码进内存 LRU（容量 ~8 张）
- GIF 动图：`<img>` 叠加层播放（Canvas 不做帧动画）

### 3.4 批量处理（batch.rs）

- 任务队列 + rayon 并行执行，进度经 Tauri 事件流推送前端
- 重命名（模板：{原名}{序号:n位}{日期:yyyy-MM-dd} 组合）、转换（JPG/PNG/WebP + 质量）、压缩、缩放
- 可取消（AtomicBool 检查点）；默认输出到 `pixlens_output/` 子目录，可选覆盖

### 3.5 基础编辑（edit.rs + 前端面板）

- 裁剪：前端矩形选区 → 传 ROI 给 Rust 裁剪落盘（保持原分辨率）
- 旋转/翻转保存、亮度/对比度/饱和度（前端实时预览，保存时 Rust 应用）
- 保存策略：默认另存副本，用户可选覆盖；JPEG 重编码质量可调

## 4. 自定义协议与数据流

```
thumb://pixlens/?src=<URL编码的绝对路径>&w=<目标宽>          → 缩略图 JPEG
tile://pixlens/?src=...&x=&y=&w=&h=&scale=                   → 大图分块（M2+）
image://pixlens/?src=...&maxDim=...&page=...                 → 查看器整帧（M2）

invoke scan_folder(path) → Vec<Entry>          # 小 JSON，正向
invoke batch_submit(任务) / edit_apply(参数)    # 小 JSON，正向
Tauri 事件：scan-partial / batch-progress / fs-changed   # 反向推送
```

## 5. 缓存设计

```
%LOCALAPPDATA%\com.pixlens.app\cache\thumbs\
  {blake3(路径+大小+mtime)[..24]}_{宽}.jpg
```

- 键含 mtime/size：文件变化自动失效，无脏缓存问题
- LRU 淘汰：默认上限 1GB，可配 256MB ~ 8GB（设置页）
- AVIF/SVG 透传项：缓存原始字节副本（浏览器端解码显示）
- 卸载清理：NSIS 卸载脚本删除缓存目录

## 6. PSD / PSB 自研解析器（codecs/psd.rs）—— 头号特色模块

### 6.1 文件结构（全部大端字节序）

```
[头部 26B]
  签名 "8BPS"(4B) · 版本 u16（1=PSD，2=PSB）· 保留 6B（全零）
  通道数 u16 · 高度 u32 · 宽度 u32 · 深度 u16（1/8/16/32）· 颜色模式 u16

[颜色模式数据]  长度 u32(PSD) / u64(PSB) + 数据（仅索引/双色调有意义，跳过）

[图像资源]     长度 u32(PSD) / u64(PSB)；内部为资源记录序列：
     "8BIM"(4B) + 资源ID u16 + Pascal名(偶数对齐) + 数据长度 u32(PSD)/u64(PSB) + 数据
     ★ 资源ID 1036 = 内嵌缩略图（JFIF JPEG）—— 快路径直接提取返回

[图层与蒙版]   长度 u32(PSD) / u64(PSB)，v1 整体跳过（查看器只看合成图）

[图像数据]     压缩方式 u16（0=Raw，1=RLE）
     RLE：先存"每行压缩字节数"表（行数×通道数 个 u16(PSD)/u32(PSB)）
     数据平面排列：ch0 全部行 → ch1 全部行 → ...（Raw 同样平面排列）
     RLE 解压 = PackBits 算法
```

PSD 与 PSB 的差异**仅在三处长度字段**（u32 → u64）与版本号，解析器统一处理，一个实现覆盖两种格式。

### 6.2 解码流程

1. `memmap2` 映射整个文件（GB 级 PSB 零拷贝），校验头部签名/版本/尺寸上限
2. 跳过颜色模式数据段
3. **快路径**：扫图像资源段，命中 1036 → 直接返回内嵌 JPEG（缩略图请求 <1ms 出图，不读合成图）
4. 跳过图层与蒙版段
5. **合成图解码**：按压缩方式逐通道解行（Raw 直读 / RLE 逐行 PackBits），行块粒度扔给 rayon 并行
6. 平面 → 交错转换：RGB(3 通道) / 灰度(1 通道) + 可选 Alpha → RGBA8
   - 深度 16：>>8 归一化；深度 32（HDR）：线性→sRGB 基础曝光映射（M4 精化）
7. RGBA8 缓冲交给缩略图管线（缩放+编码）或查看器（整帧/分块）

### 6.3 颜色模式支持矩阵（v1）

| 模式 | 支持 |
|---|---|
| RGB (3)、灰度 (1) | ✅ 完整（含 Alpha） |
| CMYK (4)、Lab (9)、索引 (2)、多通道 (7)、双色调 (8)、位图 (0) | 显示"暂不支持此色彩模式"占位，backlog |

### 6.4 护栏（防损坏/超大文件拖垮）

- 头部尺寸上限校验（宽高 ≤ 300,000，PSB 规格上限）
- 总像素超过阈值（约 8 亿像素）时拒绝全量合成，仅走内嵌缩略图/占位
- 行字节数表与文件实际长度交叉校验，防越界读
- 所有解码经信号量限流，单元测试覆盖构造的合成 PSD/PSB 样本（Raw + RLE、PSD + PSB、多深度）

## 8. 技术决策记录

| # | 决策 | 理由 | 日期 |
|---|---|---|---|
| A1 | 大数据走自定义协议，不走 JSON IPC | 避免 MB 级 base64 序列化开销 | 2026-09-20 |
| A2 | PSD/PSB 自研解析器 | 无重依赖、许可干净、PSB 大文件 mmap+并行可控（对比见 02 §4） | 2026-09-20 |
| A3 | 前端无框架 | Canvas 为主的应用，包体与升级负担最小 | 2026-09-20 |
| A4 | AVIF/SVG 走 WebView 原生解码 | 免集成 C 库，构建链简单 | 2026-09-20 |
| A5 | 缓存键含 size+mtime | 文件变化自动失效，无需主动清缓存 | 2026-09-20 |
